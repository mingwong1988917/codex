# 改造成其他类目的数据清洗 Skill

如果只清洗一次，可以直接向 Codex 提供数据和筛选要求。如果会反复清洗同一类目，可以以本 Skill 为模板，复制成一个独立的新 Skill。

不要仅把“杯壶”替换成新的类目名称。SKU 拆分、配件排除、母品合并、字段含义和验收规则都需要结合目标类目重新定义。

## 可以直接发给 Codex 的提示词

将【目标类目】替换成实际类目，并提供具有代表性的样例数据和期望的输出。

```text
请使用 skill-creator，以我提供的
building-drinkware-product-pools Skill 为模板，
复制并改造成一个【目标类目】数据清洗 Skill。

要求：
1. 不修改原来的杯壶 Skill。
2. 保留原始数据不变、证据可追溯、不猜测缺失数据等通用原则。
3. 不直接把“杯壶”替换成类目名称。
4. 先检查我提供的【目标类目】样例数据，识别字段和数据层级。
5. 重新定义：
   - 有效商品范围
   - 配件、赠品和套装排除规则
   - SKU拆分维度
   - 母品合并条件
   - 价格和销量归属口径
   - 最终输出表格
   - 验收规则
6. 同步修改 SKILL.md、references、校验脚本和 openai.yaml。
7. 完成后运行 quick_validate.py 验证新 Skill。
```

如果接收方的工具没有 `skill-creator`，仍可据上述要求改造，但应说明缺少该工具，并使用可用方式检查 Skill 的名称、入口、引用文件及脚本。`quick_validate.py` 仅检查 Skill 结构，不能替代真实样例的清洗验证。

## 改造前需要明确的规则

- 什么算一个有效商品？
- 哪些属于配件、赠品、套装，需要排除？
- 一条链接里的哪些规格需要拆行？
- 颜色、尺寸、容量、型号中，哪些是分析维度？
- 哪些商品可以合并为同一个“母品”？
- 价格、销量、付款人数是链接级还是 SKU 级？
- 最终需要输出哪些表格和图片？

原 Skill 的容量、杯壶材质、散点图坐标、图片和 Top N 展示规则是杯壶工作流的具体约定，应按新目标决定是否保留。

例如鞋类，需要根据分析目标决定按鞋款、颜色或功能系列拆分，不能直接按杯壶的容量规则拆行，也不能默认把每个鞋码当成独立商品。配件识别和同一母品的判断条件也需要重新定义。

## 需要同步修改的文件

| 文件 | 需要修改的内容 |
| --- | --- |
| `SKILL.md` | Skill 名称、适用类目、总体清洗流程 |
| `references/rules.md` | 类目识别、配件排除、SKU 拆分、母品合并和字段规则 |
| `scripts/validate_pool.py` | 表名、列名、行数、图片及必填字段验证 |
| `agents/openai.yaml` | 中文显示名称、简介和默认提示词 |

新 Skill 的文件夹名称、`SKILL.md` 的 `name` 和默认提示词中的调用名称应保持一致。使用目标类目的真实样例核对结果后，再投入重复使用。
